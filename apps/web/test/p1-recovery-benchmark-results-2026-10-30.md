# 完整分镜恢复流程性能与质量验收报告（2026-10-30）

## 结论

- [x] 实际模型输出 token 总量下降：16,853 → 8,292，减少 **50.8%**。包含全部响应，不筛选成功批次。
- [x] 完整分镜恢复流程的 fallback 场景数量已实测：旧版 **44/60**，新版 **0/60**。

## 环境与方法

同机 Ollama `0.40.12`、模型标签 `qwen3:4b`，模型摘要为 `15ab58b395867c33c78c8825bdbf3b3c96822c77dd92d937d1c1a4702b37c55d`。使用固定的 20 章中文资料，每轮七批，新旧各三轮；顺序为旧→新、新→旧、旧→新。模型预热一次，预热不计入结果。

旧版取自 P1 修改前的 `b809bb9`，新版取自 `e8b7af9`，使用最终生产提示词。脚本直接加载这两个版本的生产 `ollamaChapters()`、分组、解析、业务校验、`recoverAndCommitStoryboardBatch()` 和 fallback 代码。临时模块仅导出私有函数、在 `fallbackChapter()` 入口计数，不改写请求或响应。每批完成恢复后写入文件 checkpoint，`preferLocalAI=false`。

每次真实响应均记录 `eval_count`、`prompt_eval_count`、`eval_duration`、结束原因及耗时；无效输出与重试请求均纳入统计。fallback 数量覆盖缺失场景、业务校验失败和恢复失败后的本地回退。

## 完整流程与质量核对

| 指标（三轮合计） | 旧版 | 新版 |
| --- | ---: | ---: |

| prompt_eval_cached_count | 12,653 | 5,948 |

| JSON 解析或顶层列表错误 | 0 | 0 |
| 逐章重试请求数 | 0 | 0 |

| 最终合法场景 | 60/60 | 60/60 |

本次真实模型没有触发需要逐章恢复的 JSON 解析或顶层列表错误，因此逐章重试数为 0；恢复入口已实际执行，不能将 0 次重试解释为跳过恢复流程。旧版的 44 次 fallback 来自缺少场景、duration 类型错误、非法场景类型、visual 结构或内容不满足业务要求等情况。新版 60 个场景全部来自通过校验的模型结果。最终旁白总字符数增加约 6.4%，未通过减少最终文字总量取得本次收益；字符数与 schema 校验不等同于完整语义质量评价。

核对全部 42 条原始请求记录与六轮汇总的 token 加和一致，无重复请求编号；六份 checkpoint 均为 20 个场景且场景 ID 唯一。32 项 P0/P1 回归测试通过，包含截断逐章重试、部分失败 fallback、HTTP/连接错误分类和 checkpoint 时机；Web 类型检查通过。

## 范围与限制

本次测量覆盖分镜生成、业务校验、恢复及文件 checkpoint 链路，不包含素材提取、数据库/UI、配音和视频渲染。沿用生产默认采样设置，未固定随机种子。总耗时减少 51.2%，但其中包含提示缓存影响，不能作为冷提示首 token 延迟的测量结论。

结果反映本机模型、这份 20 章合成资料以及 P1 改动的整体效果，不将降幅单独归因于某一个字段优化，也不代表所有资料均有相同收益。此前直接模型对照的旧版提示词是手工构造的近似提示，且没有完整后处理；本报告使用真实版本代码，应以本报告作为这两个验收项的依据。此前报告中“格式错误均会逐章重试”的表述不准确：部分结构问题会直接进入业务 fallback。

## 复现与证据

运行命令：

```powershell
$env:P1_RECOVERY_OUTPUT = 'outputs/p1-recovery-benchmark-new-run'
node node_modules/tsx/dist/cli.mjs apps/web/test/p1-recovery-benchmark.ts
```

每次复测需使用新的输出目录，脚本拒绝混入已有请求记录。

- 基准脚本：`apps/web/test/p1-recovery-benchmark.ts`
- 环境、逐请求指标、响应摘要及汇总：`apps/web/test/p1-recovery-benchmark-results-2026-10-30.json`
- 本地原始请求/响应：`outputs/p1-recovery-benchmark/requests.jsonl`
- 本地各轮 checkpoint：`outputs/p1-recovery-benchmark/{baseline,current}-{1,2,3}-checkpoint.json`

原始记录及响应的 SHA-256 保存在结果 JSON 中，可用于核验。原始响应和 checkpoint 在本地输出目录保留，未上传到 issue。
